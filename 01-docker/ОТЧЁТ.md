# Отчёт. Задание 1. Docker. Начало работы

## Цель

Установить Docker, запустить контейнеры из готовых образов, пробросить порт, задать переменные окружения, связать контейнеры через `--link` и через пользовательскую сеть, оформить определения основных понятий.

## Ход работы

1. Проверена установка Docker Desktop (сервер Docker отвечает на `docker version`).
2. Запущен проверочный контейнер `hello-world`. Он скачивает образ, печатает приветствие и завершается. Это подтверждает, что демон принимает команды и умеет тянуть образы из Docker Hub.
3. Создан контейнер Ubuntu 22.04 с именем `MyUbuntu2204`. Без долгоживущего процесса контейнер сразу останавливается, `docker attach` к остановленному контейнеру не подключается. Контейнер удалён (`docker rm`) и создан заново с интерактивной оболочкой: `docker run -it --name MyUbuntu2204 ubuntu:22.04 /bin/bash`.
4. Переменная окружения задаётся флагом `-e`. Команда `docker run -it -e "MyVar=TTIT" --name MyUbuntu2304 ubuntu:23.04 /bin/bash` и внутри контейнера `echo $MyVar` выводит `TTIT`.
5. Каталог хоста монтируется флагом `-v внешний_путь:путь_в_контейнере`. Файлы, созданные на хосте в примонтированном каталоге, видны в контейнере.
6. Веб-сервер: `docker run --name MyWebServer -p 8080:80 -d nginx`. Флаг `-d` отправляет контейнер в фон, `-p 8080:80` публикует порт 80 контейнера как порт 8080 хоста. Страница приветствия Nginx открывается по адресу `http://127.0.0.1:8080`.
7. Связка MySQL и phpMyAdmin. Том `mysql_volume` хранит данные `/var/lib/mysql` после удаления контейнера. Пароль суперпользователя передаётся переменной `MYSQL_ROOT_PASSWORD`. Сначала контейнеры связаны через `--link MySQL:db`, затем остановлены и собраны заново в сети `docker_network` (`docker network create -d bridge docker_network`). Для phpMyAdmin хост базы задаётся `PMA_HOST=MySQL`: в одной сети контейнеры резолвятся по имени.
8. Список контейнеров — `docker ps -a`. Остановка и удаление — `docker stop` и `docker rm`. Неиспользуемые образы чистятся командой `docker image prune`.

Полный список команд — в `commands.md`.

## Определения

- **Docker** — платформа контейнеризации. Она собирает приложение вместе со средой выполнения и запускает его изолированно от остальной системы.
- **Образ (image)** — неизменяемый шаблон: код, зависимости, переменные и настройки. Из одного образа можно создать сколько угодно контейнеров. Тег (`nginx:latest`, `ubuntu:22.04`) указывает конкретный снимок образа.
- **Контейнер** — запущенный из образа изолированный процесс со своей файловой системой, сетью и лимитами. Пока жив главный процесс контейнера, жив и контейнер.
- **Docker Hub** — публичный реестр образов. `docker run nginx` скачивает образ оттуда, если его нет локально.
- **Dockerfile** — текстовый рецепт сборки своего образа: `FROM`, `RUN`, `COPY`, `ENV`, `EXPOSE`, `CMD`.
- **Том (volume)** — хранилище вне жизненного цикла контейнера. Каталог контейнера можно примонтировать к тому или к папке хоста (`-v`), иначе данные пропадут вместе с контейнером.
- **Проброс портов (`-p`)** — публикация порта контейнера на хост. Запись `8080:80` означает «порт 80 внутри, порт 8080 снаружи».
- **Сеть Docker** — виртуальная сеть, в которой контейнеры видят друг друга по имени. Тип `bridge` используется по умолчанию.
- **Docker Compose** — описание группы контейнеров в одном YAML-файле и запуск этой группы одной командой. Подробно разбирается в задании 2.
- **Демон и клиент** — фоновая служба Docker исполняет операции с контейнерами, а команда `docker` — это клиент, который передаёт демону запросы.

## Вывод

Контейнер — изолированный процесс, собранный из образа. Порты наружу сами не открываются, данные без тома не сохраняются, а общее имя в пользовательской сети заменяет ручной `--link`, когда контейнеров больше двух. Эти свойства проверены на `hello-world`, Ubuntu, Nginx, MySQL и phpMyAdmin.
