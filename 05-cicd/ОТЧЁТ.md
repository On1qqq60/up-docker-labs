# Отчёт. Задание 5. Автоматическая сборка CI/CD

## Цель

Собрать приложение Node.js в образ и настроить GitHub Actions так, чтобы push в ветку `main` публиковал образ на Docker Hub.

## Приложение

`app.js` поднимает Express на порту 4000 и на `GET /` отвечает `Hello World!!`. Скрипт `npm start` запускает `node app.js`.

Локальная проверка:

```bash
npm install
npm start
```

Адрес: `http://localhost:4000`.

Образ (в методичке базовый образ `node:19` и команда `docker build . --tag node_app`):

```bash
docker build . --tag node_app
docker run --rm -p 4000:4000 node_app
```

В Dockerfile использован `node:20-alpine`: 19-я ветка снята с поддержки, а синтаксис `CMD = ["npm","run","start"]` из части конспектов невалиден. Рабочая инструкция — `CMD ["npm", "run", "start"]`.

## Docker Hub

В аккаунте Docker Hub создаётся Access Token (Account settings → Security → New Access Token) с правом записи. Токен показывается один раз. В репозитории GitHub: Settings → Secrets and variables → Actions → два секрета:

- `DOCKERHUB_USERNAME` — логин Docker Hub
- `DOCKERHUB_TOKEN` — токен доступа

## Workflow

Файл `05-cicd/.github/workflows/main.yml` — workflow самого приложения, как в методичке (имя `node_app`, событие `push` в `main`). Поскольку эта учебная практика лежит одним репозиторием, GitHub читает workflow только из корневого `.github`. Поэтому тот же конвейер продублирован в `.github/workflows/node-app.yml` и собирает контекст `./05-cicd`.

Шаги: `actions/checkout` забирает код, `docker/login-action` входит в Docker Hub секретами, `docker/setup-buildx-action` готовит сборщик, `docker/build-push-action` собирает Dockerfile и пушит тег `ВАШ_ЛОГИН/clockbox:latest`.

Версии actions подняты до актуальных (`checkout@v4`, `login-action@v3`, `setup-buildx-action@v3`, `build-push-action@v6`): v2/v3 из статьи 2023 года на новых раннерах GitHub больше не запускаются. Смысл шагов тот же.

## Что нужно сделать на своих аккаунтах

1. Создать репозиторий и запушить эту практику в ветку `main`.
2. Записать два секрета. Без них шаг входа в Docker Hub завершится ошибкой — так и задумано, токен в репозиторий класть нельзя.
3. Открыть вкладку Actions и дождаться зелёной сборки. Образ появится в Docker Hub как `<логин>/clockbox:latest`.

## Вывод

CI/CD здесь сводится к одному workflow: событие push запускает сборку образа и публикацию в реестр. Секреты отделяют токен от кода, поэтому репозиторий можно показывать, не раскрывая доступ к Docker Hub.
