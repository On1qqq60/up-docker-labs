# Отчёт. Задание 3. Упаковка приложения в Docker-контейнер

## Цель

Собрать собственные образы для двух приложений — Flask и Node.js — и запустить их как контейнеры.

## Flask

Приложение `flask_app/hello.py` отвечает `Hello World!` на `/`. Локально его запускают так: создать виртуальное окружение, установить Flask, задать `FLASK_APP=hello.py` и выполнить `flask run` (порт 5000). В образ приложение слушает порт 8000, как в методичке (`docker run -p 127.0.0.1:8000:8000`).

Dockerfile берёт `python:3.12-slim`, ставит зависимости из `requirements.txt` отдельным слоем и копирует `hello.py`. Контекст сборки — каталог `flask_app`, поэтому и Dockerfile, и `hello.py` должны лежать в нём.

```bash
cd flask_app
docker build -t appflask:latest .
docker run --rm -p 127.0.0.1:8000:8000 appflask:latest
```

Проверка: `http://127.0.0.1:8000`.

## Node.js

Каталог `app_node` повторяет официальный пример докеризации Node.js, на который ссылается методичка. `package.json` описывает приложение и зависимость Express. `server.js` слушает `0.0.0.0:8080` и отвечает `Hello World`.

Dockerfile копирует сначала только `package*.json` и выполняет `npm install`, и только потом копирует остальной код. Так слой с зависимостями не пересобирается при правке `server.js`. `.dockerignore` исключает `node_modules`, чтобы в образ не попали модули с хоста.

```bash
cd app_node
docker build -t appnode:latest .
docker run --rm -p 49160:8080 appnode:latest
```

Проверка: `http://127.0.0.1:49160`.

## Вывод

Образ фиксирует язык, зависимости и команду запуска. Один и тот же образ стартует на любой машине с Docker без отдельной установки Python или Node.js. Порядок слоёв в Dockerfile (сначала манифест зависимостей, потом код) сокращает повторные сборки.
