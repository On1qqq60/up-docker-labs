# Отчёт. Задание 8. Dev и prod окружение

## Цель

Разделить окружения разработки и продакшена одним комплектом файлов: два compose-файла, общий `.env`, контейнеры Node.js, Nginx, Postgres и pgAdmin. Основание — статья «Прочный фундамент для API: Docker + Node.js + Nginx + Postgres».

## Состав

- `.env` — `NODE_ENV`, параметры базы (`DB_NAME=api`, пользователь `postgres`, пароль `secret007`, хост `db`) и `COMPOSE_FILE`.
- `docker-compose.dev.yml` — цель сборки `dev`, исходники смонтированы в контейнер, `node_modules` ставятся внутри.
- `docker-compose.production.yml` — цель `production`, команда `npm run start`, анонимный том `/opt/server/node_modules/`, чтобы модули контейнера не затирались каталогом хоста.
- `app/Dockerfile` — две стадии, `dev` и `production`. В методичке базовый образ `node:16.10.0-alpine`; эта метка больше не публикуется, использован `node:18-alpine`. Часовой пояс `Europe/Moscow`.
- `nginx/nginx.conf` — корень `/`, статика из `/var/www/static`, остальное проксируется на `app:3000`, путь `/pgadmin` — на контейнер pgAdmin.
- `static/file.txt` — файл, который Nginx отдаёт сам.

Compose не раскрывает `${NODE_ENV}` внутри самого `.env`, поэтому `COMPOSE_FILE` записан готовой строкой `docker-compose.dev.yml`. Для продакшена в `.env` меняются две строки: `NODE_ENV=production` и `COMPOSE_FILE=docker-compose.production.yml`.

## Запуск разработки

Из каталога `08-dev-prod`:

```bash
docker compose up --build -d
docker compose exec app sh
npm install express nodemon pg
npm install --save-dev eslint
npm run dev
```

`package.json` и `app.js` уже лежат в каталоге и смонтированы в `/opt/server`, поэтому `npm install` подтягивает зависимости, а не создаёт приложение с нуля. Контейнер `app` в dev не запускает сервер главным процессом: методичка входит в контейнер и стартует nodemon отдельно. Чтобы `exec` работал после `up -d`, процесс контейнера — `sleep`. В методичке на этом месте команда `node`, но без подключённого терминала интерпретатор сразу завершается.

Команды в `package.json`:

- `start` — `nodemon ./app.js` (её вызывает production);
- `lint` — `eslint app.js`;
- `dev` — `nodemon ./app.js --exec "npm run lint && node"`.

Конфиг ESLint — проверка синтаксиса, CommonJS, без фреймворка и без TypeScript, среда Node, файл JSON. Это те ответы, которые методичка предлагает выбрать в `npm init @eslint/config`.

Пока nodemon запущен, `http://localhost/` возвращает `{ "message": "Hello World" }`. Если процесс остановить, Nginx отвечает 502. Файл `http://localhost/file.txt` при этом продолжает открываться.

## База

Образ Postgres создаёт пользователя из `DB_USER` / `DB_PASSWORD`, но базу `api` сам не создаёт — в `.env` она указана для приложения, а не как `POSTGRES_DB`. Её создают в pgAdmin:

1. Открыть `http://localhost/pgadmin` (если Nginx показал ошибку, обновить страницу).
2. Войти: `info@proglib.io` / `qwertyuiop`.
3. Register → Server. На вкладке General — любое имя. На вкладке Connection: host `db`, user `postgres`, password `secret007`, maintenance database `postgres`.
4. Правой кнопкой по Databases → Create → Database, имя `api`.
5. Перезапустить `npm run dev`. В логе появится результат `SELECT NOW()`.

Той же цели служит команда `docker compose exec db psql -U postgres -c "CREATE DATABASE api;"`.

Пул соединений в `app.js` после проверки не закрывается. В конспекте есть `pool.end()`, но тогда сервер теряет доступ к базе сразу после первого запроса.

## Продакшен

В `.env` выставить `NODE_ENV=production` и `COMPOSE_FILE=docker-compose.production.yml`, затем:

```bash
docker compose up --build -d
```

Стадия `production` сама выполняет `npm i` и команду `npm run start`. Каталог `node_modules` живёт только в контейнере, на хост и в git он не попадает.

Возврат к разработке: вернуть две строки в `.env`, снова `docker compose up --build -d`, зайти в контейнер, при необходимости повторить `npm install` и запустить `npm run dev`.

## Вывод

Разница окружений сосредоточена в цели Dockerfile и в одном флаге `COMPOSE_FILE`. Код, Nginx и база общие. В разработке исходники смонтированы и перезапускаются nodemon, в продакшене зависимости ставятся при сборке образа и не зависят от того, есть ли `node_modules` на машине.
