# Отчёт. Задание 2. Docker Compose

## Цель

Описать несколько контейнеров одним файлом `docker-compose.yaml` и поднять веб-приложение: Nginx, PHP-FPM, MariaDB и phpMyAdmin.

## Ход работы

Каталог проекта соответствует `app_docker` из методички. Файл `docker-compose.yaml` использует синтаксис версии 3.5 и три обязательные секции: `networks`, `volumes`, `services`.

1. Сервис `docker-nginx` собран из образа `nginx`. Порт 80 опубликован как 8094 (`localhost:8094`). Каталог проекта примонтирован в `/var/www/html`, поэтому `index.html` на хосте сразу виден в браузере.
2. Сервис `docker-mariadb` хранит данные в томе `ttit-vl`, а не в слое контейнера. Пароль root, имя базы и пользователь заданы в `environment`: `MYSQL_ROOT_PASSWORD=root`, база `app`, пользователь `user` / `password`.
3. Сеть `ttit-network` подключена ко всем сервисам. phpMyAdmin обращается к базе по имени сервиса: `PMA_HOST=docker-mariadb`. Веб-интерфейс опубликован на порту 8095. Вход: сервер уже подставлен, пользователь `root`, пароль `root`.
4. Для PHP написан свой образ. `php-fpm/Dockerfile` начинается с `FROM php:8.3-fpm` и командой `RUN docker-php-ext-install pdo_mysql mysqli` ставит расширения. В compose у этого сервиса вместо `image` указан `build: ./php-fpm`.
5. `nginx/site.conf` отдаёт статику и передаёт файлы `*.php` в `docker-php-fpm:9000`. `index.php` печатает версию PHP. Общий путь `/var/www/html` смонтирован и в Nginx, и в PHP-FPM, поэтому `SCRIPT_FILENAME` указывает на файл, который реально есть в контейнере PHP.
6. Запуск из каталога задания: `docker compose up --build`. В фоне: `docker compose up -d`. Оболочка Nginx: `docker compose exec docker-nginx sh` (в alpine-образе оболочка `sh`, не bash). Остановка без удаления — `docker compose stop`, остановка с удалением контейнеров — `docker compose down`. Том `ttit-vl` при `down` сохраняется; `docker compose down -v` удалит и его.

## Вывод

Compose заменяет длинную цепочку `docker run`: порты, тома, переменные, сеть и сборка своего образа описаны в одном файле. Контейнеры одной сети обращаются друг к другу по имени сервиса, а код сайта остаётся на хосте и подхватывается без пересборки образа.
