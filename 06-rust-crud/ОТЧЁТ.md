# Отчёт. Задание 6. CRUD API на Rust, Postgres и Docker

## Цель

Собрать HTTP API пользователей на Rust без веб-фреймворка, хранить записи в Postgres и запускать оба сервиса через Docker Compose. Источник методики — Francesco Ciulla, Rust CRUD Rest API.

## Приложение

Каталог создаётся как обычный crate с именем `rust-crud-api`. Зависимости в `Cargo.toml`: `postgres`, `serde`, `serde_json`, `serde_derive`.

`src/main.rs`:

- модель `User` с полями `id: Option<i32>`, `name`, `email`. Идентификатор необязателен: его выдаёт `SERIAL` в базе. `#[serde(default)]` позволяет создавать пользователя телом без поля `id`;
- адрес базы зашивается на этапе сборки: `const DB_URL: &str = env!("DATABASE_URL");`
- ответы `200`, `404` и `500` заданы константами с заголовком `Content-Type: application/json`;
- `TcpListener` слушает `0.0.0.0:8080`. На каждое соединение `handle_client` читает запрос и выбирает обработчик по первой строке: `POST /users`, `GET /users/`, `GET /users`, `PUT /users/`, `DELETE /users/`;
- `set_database` создаёт таблицу `users`, если её нет;
- `get_id` достаёт идентификатор из URL, `get_user_request_body` разбирает JSON после пустой строки заголовков.

Дополнение к конспекту: процесс до 30 раз повторяет подключение к базе с паузой 2 секунды. Postgres в соседнем контейнере принимает соединения не в ту же миллисекунду, когда Compose его запустил, и без повтора API завершался бы с ошибкой. В запросах перечислены столбцы `id, name, email`, чтобы порядок полей не зависел от того, как Postgres вернёт `SELECT *`.

## Docker

`.dockerignore` исключает `target`, чтобы в контекст сборки не попал локальный каталог сборки.

Dockerfile — многоступенчатый. Стадия `builder` (`rust:1-bookworm`, актуальный стабильный компилятор) ставит `libpq-dev` и выполняет `cargo build --release`. Аргумент `DATABASE_URL` обязателен: макрос `env!` срабатывает при компиляции. Если аргумент не передан, в Dockerfile подставлена та же строка, что и в compose. Стадия запуска (`debian:bookworm-slim`) копирует только бинарник `rust-crud-api` и библиотеку `libpq5`. В конспекте указаны `rust:1.69-buster` и `debian:buster-slim`. Эти образы сняты с публикации, а свежие версии крейтов на crates.io требуют Rust с edition 2024, поэтому сборка идёт на текущем стабильном образе. Схема стадий та же.

`docker-compose.yml` описывает `rustapp` и `db`. Строка подключения `postgres://postgres:postgres@db:5432/postgres`: хост `db` — имя сервиса Postgres. Том `pgdata` хранит данные. `restart: on-failure` поднимает API повторно, если первая попытка попала в ещё не готовую базу.

```bash
docker compose up --build
```

## Проверка

Пустая база отвечает на список пустым массивом:

```bash
curl http://localhost:8080/users
```

Создание:

```bash
curl -X POST http://localhost:8080/users -H "Content-Type: application/json" -d "{\"name\":\"Иван\",\"email\":\"ivan@example.com\"}"
```

Дальше те же маршруты: `GET /users/1`, `PUT /users/1` с новым JSON, `DELETE /users/1`. Заголовок `Content-Type: application/json` обязателен по смыслу тела; сам разбор смотрит только на JSON после заголовков.

Публикация на Docker Hub делается тем же способом, что в задании 5: `docker login`, затем `docker tag` и `docker push`. Секреты в репозиторий не кладутся.

## Вывод

API обошёлся стандартной библиотекой (`TcpListener`) и драйвером Postgres. Compose связал приложение с базой по имени сервиса, а многоступенчатая сборка оставила в итоговом образе только бинарник, без компилятора Rust.
